# Paw Still Here

[pawstillhere.com](https://pawstillhere.com) · As long as they're remembered, they're still with us.（只要它们被记得，就一直和我们在一起。）

用 Three.js 做的在线宠物纪念馆：沿着石头路走进没有屋顶的大厅，正中是一棵纪念树（The Remembering Tree），左墙和正面墙是 A、B 两个区的照片墙，右墙是影厅和「思念之河」的入口，在夜空、流星和孔明灯下看看那些一直被记得的小家伙。

界面和场景里的文字目前只有英语，结构上支持多语言（见下面的「文字与多语言」）。本文档里引号中的按钮名是意思，界面上显示的是对应的英文。

## 启动

```bash
pnpm install
pnpm dev          # 同时启动前端（5173）与 API（8787）
pnpm dev:web      # 只启动前端
pnpm dev:api      # 只启动 API
pnpm build        # 各 workspace 类型检查 + 前端打包到 apps/web/dist/
pnpm typecheck    # 仅类型检查
pnpm test         # API 单元测试
```

本地开发时，前端的 `/api` 会代理到 `http://localhost:8787`。健康检查：`curl http://localhost:8787/api/health`。

首次跑 API 前：

```bash
cp apps/api/.dev.vars.example apps/api/.dev.vars   # 填 BETTER_AUTH_SECRET；上传需 R2 密钥
pnpm --filter @paw/api db:migrate:local
```

前端环境变量（可选，见下节「环境变量」）：`cp apps/web/.env.example apps/web/.env`。

本项目是 pnpm monorepo：`apps/web` 为 Three.js 前端，`apps/api` 为部署在 **Cloudflare Worker** 上的 Hono API（D1 + Better Auth 匿名登录 + R2 预签名上传），`packages/shared` 为 Zod/DTO 契约。

## 环境变量

按**谁读这个文件**来分，和 TanStack 全栈 Worker 模板（`references/my-template`，未入库）思路相同：Vite 用 `.env*`，Wrangler 用 `.dev.vars` + `vars` + secret。本仓库前后端拆开，所以文件落在不同 app 里。

| 放哪里 | 谁读 | 放什么 |
| --- | --- | --- |
| `apps/api/.dev.vars` | `wrangler dev` / Worker | **密钥**：`BETTER_AUTH_SECRET`、R2 API 密钥等（模板见 `.dev.vars.example`） |
| `apps/api/wrangler.jsonc` → `vars` | 本地与生产 Worker | **非密**、Worker 要读的公开配置，如 `BETTER_AUTH_URL`、`PUBLIC_ASSETS_URL` |
| `apps/api/wrangler.jsonc` → `d1_databases` / `r2_buckets` | Worker 绑定 | D1、R2 **资源绑定**，不是 `.env` 字符串 |
| `apps/web/.env` | Vite | 仅 **`VITE_` 开头**、需要进浏览器或 dev server 的变量（模板见 `.env.example`；默认可不建） |
| 生产 | `wrangler secret put` / Dashboard | 与 `.dev.vars` 同类密钥，**不进 git** |

简易判断：**绝不能进浏览器** → API 的 `.dev.vars` / `wrangler secret`；**前端 JS 要读到** → `apps/web/.env` 且 `VITE_`；**公开且 Worker 用** → `wrangler.jsonc` 的 `vars`。

本地最小配置：只复制并填写 `apps/api/.dev.vars`（至少 `BETTER_AUTH_SECRET`）。前端的 `/api` 由 `apps/web/vite.config.ts` 代理到 `8787`，不依赖 `.env`。

底部按钮可以一键传送到入口（Gate）、码头（Dock）、篝火（Fire）、孔明灯平台（Lanterns）、大厅（Lobby），也可以打开信（Letters）、查找宠物（名字、品种或区，如 `luna`、`poodle`、`a`、`section b`，不区分大小写）。大厅接待台可以点击（查找宠物），纪念树两侧的沙发点一下可以坐下。

### 河灯

入口步道中途有一条河，步道在这里变成一座石拱桥。桥头靠入口一侧有个小码头，点击码头上摆着河灯的木台，就能放下一盏河灯，看它在水面上亮着顺水漂开。可以直接放，也可以先搜一只宠物，灯上就会写着它的名字。

### 纪念树上的信

大厅正中的纪念树下挂着一块块小木牌，每块木牌是一封信（牌子上不写字，只是一个意象）。信有两种：写给某一只宠物的，同时留在它的纪念角里；没有写给某一只的，是写给这里所有小家伙的（原来的留言簿）。烧掉的信不在其中。

两个入口打开的是同一个弹窗：底部的 Letters 按钮；点纪念树。在单宠物视角里点矮柜上的那摞信或礼物栏的信，打开的是只看写给它的那些，写的时候也已经选好了它。

弹窗打开先看到的是信：一封一张卡片，头上是它的头像和名字（没有写给某一只的是一个爪印），右边的按钮可以去看它；自己写的在前，后面是示例的。上面可以切换「全部 / 自己写的」，写信的那一块收着，点「Write a letter」才展开（可以选写给哪只）。每封信可以送一颗爱心（再点一次收回）、回一句话（只有一层）、举报。写了一封，树上朝大门的一侧就多一块浅色的、坠着一颗小亮珠的木牌（最多 12 块）。

现在没有后端：别人的信只有示例的那几封；爱心和回的话只存在自己的浏览器里，只有自己看得到；举报只是让那封信在自己这里不再出现。

### 篝火烧信

过了桥再往前，步道左侧有一块空地，中间是一堆篝火，围着几个树桩凳。点击火堆，选一只宠物，写一封信投进火里，信纸会卷曲、烧尽，化成一串火星升上夜空。烧掉的信不保存内容，只记下给它烧过一封信；想留下的信请放在它的纪念角里。

### 孔明灯

篝火对面、步道右侧有一块圆形石台：一张矮木桌上摆着几盏还没点的纸灯，后面的木架上挂着三盏亮着的灯。点击桌子，写一句话，灯就从桌面上升起，带着这句话飘上夜空。也可以选一只宠物：没写字时灯上写它的名字；什么都不填，灯上是默认的那句短标语。孔明灯只记总数，不记内容和写给谁。

三件事里只有烧信必须选一只宠物、必须写内容；河灯和孔明灯选不选都可以。

### 其他访客

馆里会有几位其他访客慢慢走动：在照片墙前、纪念树前、码头、河边和孔明灯平台站一会儿，在沙发、篝火旁的树桩凳上坐一会儿，逛几处之后从入口离开，过一阵再换一个人进来。他们只是在场，不放灯、不烧信，也不读写任何数据；人和人之间可以互相穿过。右上角的「访客：显示 / 隐藏」可以切换成独自参观，选择会记住。

现在这些访客是本地模拟的。访客的数据来源（`VisitorSource`）和绘制（`Crowd`）是分开的：以后接后端时，只需再写一个从网络接收状态的 `VisitorSource`，替换 `main.ts` 里创建 `SimulatedVisitors` 的那一行，绘制部分不用改。

### 它的客厅

点击照片墙上任意一张相框，画面暗一下再亮起来，就像从门口走进它日常居住的客厅。背墙是一扇看海上日落的大窗，两侧米白窗帘和木杆上挂着一串小灯；中央米白圆地毯上是一张三条斜腿的圆茶几，它的主照片斜放在台面一侧，旁边是书、杯子和信。左侧布艺沙发配两只橙色靠垫，上方两块木搁板放书、垂吊植物和相册里的其他照片。左侧下搁板靠窗的一端放着香薰蜡烛。右侧地面是宠物窝、食盆和散落的玩具，窝后有落地灯，食盆上写它的名字。窗边小矮柜上插着花，旁边只系一束三只气球，天花板有一组球形吊灯。屋里没有年份、铜牌或墙上大字，顶部资料也不覆盖房间。

小人和其他访客这时不出现；镜头固定在门口，按住左右拖动可以转一点角度看，竖屏仍完整保住大窗、茶几和主照片，两侧家具只露出一部分。它还有别的照片时，画面右侧会出现竖着的一列缩略图（多了可以上下滚），点任意一张打开大图，用两侧的箭头、← → 或左右滑动翻看，Esc、点 × 或点图外面收起。点家具和照片以外的地方、按 Esc 或点左上角的「Back」，画面再暗一下，回到照片墙前原来站的位置。

礼物是在给屋子添生活物件，不再供在照片前：花先插满窗边花瓶，再出现在茶几小花瓶里；玩具散在窝边；零食只在礼物栏里计数；信叠在茶几的书旁，点这摞信仍然可以读信。窗帘杆灯串是普通装饰，始终暖亮，不与礼物挂钩。左侧下搁板上只有一只 8 × 9 厘米的玻璃香薰蜡烛，没收过时罐子也在但没有火苗，收到至少一份后火苗常亮；每送一份火苗都会跳亮一下，数量只在礼物栏累计。其他新礼物在所属位置轻轻弹出，可摆放礼物的数量上限和 store 数据格式不变。有人为它放过花或点过蜡烛，照片墙上它相框下的小石台仍沿用原来的花和烛光痕迹。

每个区两端有铭牌写着区名和格号范围（如 `Section A · 1–60`），电梯旁挂着本层的总览图。进门左手是 A 区，正对面是 B 区；穿过 B 区正中的后门是一条走廊，通向 C–H 展区——三排双面展墙，两面都挂照片，中间留走道；右手那面墙不挂照片，是影厅和河的入口。

客厅拥有自己的 `THREE.Scene`、背景、雾、环境贴图和灯光，打开时只切换后期 `RenderPass.scene`，关闭立即切回主场景；不借主场景月光、天空光、灯位池或暗幕。高画质只有窗口平行光开 1024 阴影，低画质关闭它并使用家具下的模糊圆斑。全部家具在加载阶段搭好并留在内存里，静态零件按材质合并，Canvas 贴图不超过 512。每件家具由 `apps/web/src/world/PetRoom.ts` 里的独立函数返回一个米制 Group，位置、朝向和缩放集中在 `CONFIG.shrine.layout`。沙发与靠垫全部为程序生成几何体，环境光用 `RoomEnvironment`，不加载外部模型。

### 影厅

大厅右墙靠后墙的一侧有一个门洞，上面是亮着一圈小灯泡的招牌（The Memory Theater）。走进门洞后面挂着帘子的门厅，画面暗一下，就到了私人放映室：两排深红布艺沙发，后排比前排高一级矮台阶；正前方是银幕，两侧小边桌和壁灯，地上铺着深红地毯。点一张沙发，小人会走到沙发前，坐在离自己最近的位置；想走时照常移动就站起来。从后墙正中的门洞（上面写着 Lobby）走出去，回到大厅的入口前。

放映室建在主场景之外很远的地方，里面没有其他访客。银幕现在只显示馆名，放映的内容还没有做。

### 思念之河

一条穿过大山洞的河，两头都能上船：从大厅坐船出洞，或者从大门旁边坐船进洞，到大厅。两个方向用的是同一个山洞、同一条河，各走一条航道。

大厅右墙靠大门的一侧是一个石砌的拱形洞口，上面挂着木牌（The River of Longing）。

- **入口**：进洞迎面的石壁上是一个发光的箭头（To the boats），右手边是一条窄道。走进窄道（或直接点洞口），画面暗下去，换到山洞里
- **石台和石阶**：再亮起来时站在洞壁高处的石台上，整个洞厅在眼前。沿石阶走下去是贴着河道的木码头。往回走进石台后面的门洞，就回到大厅的洞口前
- **山洞**：一个很大很开阔的洞厅（最宽处约 220 米、高约 68 米），河从中间流过。洞壁是一整张粗糙的岩面，离河道很远，洞里比外面暗，但仍有底光：几盏看不见的暖色灯（像灯笼和烛火的光，中段和洞口各有一两盏很淡的月光色）照出远处洞壁和水面，水面上稀疏地漂着河灯
- **船**：每条船 6 个座位。每隔一会儿（`CONFIG.cave.boat.interval`，默认 24 秒）有一条空船靠上码头，到点就开，不等坐满，所以河面上同时有好几条船前后隔着距离一起漂。点船上的座位就走过去坐下；船开之前可以再站起来
- **同乘的访客**：别的访客也会从门洞出来、走下石阶、在码头上等、坐到船上。现在是本地模拟的（`CaveRide` 里的 `Rider`），「独自参观」时不出现
- **到岸**：船漂过洞厅，从一个很大的洞口漂到夜空下（全程一分钟左右）；到头后画面暗下去，访客站在洞口外那座码头上（还在思念之河里，沿石阶走上去、穿过写着 Gate 的门洞，才回到大门旁的石屋；不是直接跳到步道上的河灯码头）。坐上船以后不能再点码头走下来，只能等到岸，或用底部的「下船」回到这一头的入口前；船开了以后还可「放河灯」，见下一条
- **在船上放河灯**：点开的是码头上那个放河灯的弹窗（可以选一只宠物）。灯从船头前面一点、自己坐的那一侧慢慢落到水面上（那一侧正好是码头时换到另一侧），留在原地，船从它旁边漂过去；名字浮在灯上。和码头放的河灯计在一起；水面上最多留 10 盏，刷新页面后不保留
- **反方向（大门 → 大厅）**：入口步道起点（Gate）右手边有一间小石屋，挂着同样的木牌，里面是一个向下的箭头。走进去（或点它），画面暗下去，再亮起来时站在洞口外的石台上：同样的石阶、同样的木码头，只是在夜空下，面前是山和洞口。船从这里进洞，漂到洞里那座码头的另一侧靠岸，船上的人下船，沿石阶走上去，从写着 Lobby 的门洞进大厅；空船继续往洞的深处漂走。往回走进洞口外石台后面的门洞（写着 Gate），就回到小石屋前

山洞和影厅一样建在主场景之外很远的地方（`CONFIG.cave.x / z`），河道的走向（`path`）、沿途的宽窄和洞顶高度（`profile`）、船速、石台和码头的高度都在 `config.ts` 里。洞里夜空的底光会调暗（`World.setAmbience`），出洞时再亮回来。

两条航道并排：出洞的船靠洞里码头的西侧，进洞的船靠东侧（`CaveRide` 里的 `Line`，两座码头是同一套 `buildStation`）。沿途的照片和文字、在船上放河灯还没有做（洞壁上试过石面、发光的字和布幅，都去掉了，洞壁保持自然的岩石）。

## 常见修改

### 添加自己的宠物

编辑 `apps/web/src/data/pets.ts` 顶部的 `CUSTOM_PETS`。宠物按顺序住进照片墙：先填 A 区，满了到 B 区，排在前面的格号也靠前：

```ts
export const CUSTOM_PETS = [
  {
    name: 'Doudou',
    species: 'dog',           // cat | dog | rabbit | hamster | bird
    breed: 'Corgi',
    birthDate: '2012-03-01',
    passedDate: '2025-06-18',
    photoUrl: '/photos/doudou.jpg',
    message: 'Your spot on the sofa is still yours.',
  },
];
```

### 替换照片

把图片放进 `apps/web/public/photos/`，然后在宠物数据里填 `photoUrl: '/photos/文件名.jpg'`。照片会被裁成正方形。没有 `photoUrl` 的宠物使用程序生成的卡通画像。使用其他域名的图片时，对方服务器需要允许跨域（CORS）。

### 相册（多张照片）

除了照片墙上那一张，每只宠物还可以有几张照片，出现在它纪念角右侧的那一列缩略图里。在宠物数据里填 `photos: ['/photos/文件名-2.jpg', '/photos/文件名-3.jpg']`，张数不限。只填了 `photoUrl`、没填 `photos` 的宠物没有相册。示例宠物每只有两到四张程序画的占位画像。

### 替换音乐

把音乐文件放到 `apps/web/public/audio/bgm.mp3`，会自动循环播放。没有这个文件时，程序会用 WebAudio 现场合成一段舒缓的环境音乐，所以不放文件也不会报错。

### 调整场景

`apps/web/src/config.ts` 里可以改大厅的尺寸、照片墙的行列数和相框大小、宠物小屋的尺寸配色家具布置和每类礼物最多摆出的件数、河流的位置宽度流速和河灯数量、篝火的位置和烧信时长、孔明灯平台的位置和大小、影厅的大小银幕座位排数和门洞、河的洞口、小人的身高速度颜色、镜头的距离和俯仰范围、模拟访客的人数速度停留时长和衣服颜色、宠物数量、星星和孔明灯数量、流星间隔、主要颜色等。界面与场景里的文字都在 `apps/web/src/i18n/en.ts`。

### 文字与多语言

访客能看到的字都在 `apps/web/src/i18n/` 里，其余代码只用 `STR`，不直接写文字：

- `en.ts` 是完整的一份：品牌名和标语、界面、场景里的字、物种的显示名、地址的写法、示例宠物的名字品种寄语、页面信息（`meta`），以及这门语言的字体和字间距（`style`）。
- 加一种语言：照着 `en.ts` 写一个文件（比如 `zh.ts`，类型标成 `Strings`），在 `index.ts` 的 `LOCALES` 里登记。缺一条就编译不过。现在没有切换语言的入口，用哪种语言由 `index.ts` 里的 `LOCALE` 决定。
- `sample` 里各个列表的条数不要改：示例宠物是用固定的随机数从里面挑的。
- 数据里不存文字：物种是 `cat / dog / rabbit / hamster / bird`，区是 `A–H`，显示名从 `STR` 取。
- 品牌的说法：说「记得」「还在这里」，不说「去了星星上」「离开」「逝去」；日期只写起止年月日。

宠物总数上限是 2052（每层 342：A 60 + B 66 + C–H 6 × 36，最多 6 层）。后门默认打开，走廊通向三排双面展墙；一层满了自动落到下一层。楼层共享同一套 3D 大厅和展区，只替换这一层的照片、铭牌、痕迹和 `slots`，在顶部 Floor 选择器里淡入淡出切换，不重建墙体，也没有真正的 3D 楼层。

### 接入后端

礼物、信（以及对信的爱心、回的话、举报），以及放河灯、烧信的记录，读写都封装在 `apps/web/src/data/store.ts`，目前存在浏览器的 localStorage 里（键名 `jinian:v2`，改品牌名时没有动，改了会丢掉已有数据），所以每位访客只能看到自己放的东西。接后端时只需要替换这个文件里的实现。

对信的爱心、回的话、举报记在同一份数据里新增的 `social` 字段下，用信的编号对应，信本身的存法没有变；没有这个字段的旧数据照常能读。

旧版本存下的数据（键名 `jinian:v1`，只有花数、蜡烛数和留言）会在第一次打开时自动转换成新格式，原数据保留不动。

## 画质

右上角可以切换画质。「低」会关闭辉光后期和月光阴影，并降低渲染分辨率；触屏设备默认使用低画质。
